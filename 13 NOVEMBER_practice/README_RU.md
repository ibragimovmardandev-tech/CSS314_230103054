# Лабораторная: запуск и сдача

Это комплект решения и генератор отчета. Полные результаты вашего ноутбука появятся только после локального запуска. Папка smoke_results содержит сокращенный тест в среде помощника, а НЕ результаты вашего ноутбука. По условию самостоятельное упражнение выполняется без интернета и AI; учитывайте правила преподавателя при использовании этого комплекта.

## Windows: быстрый старт

1. Распакуйте архив целиком в обычную папку.
2. Откройте эту папку в терминале (PowerShell).
3. Убедитесь, что установлен Python 3.8 или новее: `py --version`.
4. Закройте тяжелые программы, подключите ноутбук к питанию и отключите интернет.
5. Выполните:

```powershell
py run_all.py --student-id 230103054
```

ID 230103054 взят из названия предыдущего отчета; замените, если он другой.
На macOS/Linux используйте `python3` вместо `py`.
Устанавливать сторонние Python-пакеты не нужно. Полный прогон может быть долгим: все размеры из задания сохранены, а каждый вариант проходит два прогрева и семь замеров.

## Что сдавать

После завершения всех пяти этапов: `results/lab_report_230103054.md`.
Он содержит таблицу оборудования, пять VERIFY_HASH, результаты, пояснения и полный исходный код всех скриптов.
Можно также приложить `results/telemetry.json` и исходные `.py`, если преподаватель просит.
Не сдавайте smoke_results в качестве полного эксперимента.

## Проверка и продолжение

```powershell
py run_all.py --quick
```

Быстрая проверка НЕ заменяет основной запуск. Она использует 1 замер и уменьшенные задачи, сохраняет данные в отдельную папку smoke_results. IQR=0 в ней не показывает стабильность.
Результаты полного запуска сохраняются после каждого этапа. Можно продолжить поэтапно:

```powershell
py task0_cal.py
py task1_falsesharing.py
py task2_scaling.py
py task3_roofline_gemm.py
py task4_scheduling.py
```

Этап N требует результаты этапов 0..N-1 с той же конфигурацией. Если перезапустили ранний этап, повторите все последующие, чтобы сохранить цепочку.

## Оборудование

Windows: CPU и ядра читаются через PowerShell/WMI, кеши через Windows API. Linux: lscpu/getconf. macOS: sysctl.
Если автоматическое определение не сработало, создайте `hardware.json` рядом со скриптами и впишите настоящие данные:

```json
{
  "CPU": "Точная модель процессора",
  "physical_cores": 4,
  "cache_line_bytes": 64,
  "L1d": "Укажите размер кеша данных на ядро",
  "L2": "Укажите размер и область совместного использования",
  "L3": "Укажите общий размер либо absent"
}
```

Числа 4 и 64 выше лишь пример, их нужно проверить. Не копируйте их вслепую.
Число логических процессоров берется из mp.cpu_count(). Перед полным запуском сравните его с диспетчером задач. Флаги `--physical` и `--logical` предназначены для явного задания конфигурации; полный режим не разрешает сокращать логический диапазон.

Исходные требования содержат ограничение: блок 4096 байт дает только 512 uint64-слотов. При stride=32 помещается максимум 16 работников, при stride=16 — 32. Если ваш процессор превышает этот предел, программа остановится с объяснением; согласуйте изменение размера с преподавателем.

## Кратко для объяснения работы

- False sharing: разные переменные в одной линии кеша создают обмен правами записи между ядрами. Увеличение stride может уменьшить конфликт.
- Karp–Flatt: e=(1/S-1/p)/(1-1/p); оценивает совокупную последовательную долю и параллельные накладные расходы.
- Strong scaling: N фиксировано; S=T1/Tp, E=S/p, предел Амдала 1/s.
- Weak scaling: N=p*N0; эффективность T1/Tp; Густафсон p-alpha*(p-1).
- Roofline: производительность ограничивается min(P, BW*I). В Python существенна стоимость интерпретатора; измеренный потолок не равен паспортному пределу CPU.
- Scheduling: блоки плохо распределяют растущую стоимость; циклическое распределение выравнивает ее; динамические чанки балансируют нагрузку ценой синхронизации.

В отчете указаны ограничения интерпретации: процессы не привязаны к ядрам; переход через Pphys не доказывает переход на SMT/E-ядра; измеренная пропускная способность не является замером DRAM аппаратными счетчиками. Операции multiply+add считаются как 2 FLOP, но не выдается утверждение о настоящей fused FMA.
